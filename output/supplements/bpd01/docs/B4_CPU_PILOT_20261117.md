# B4 CPU pass-20 pilot (source-locked 2026-11-17)

This **exploratory CPU FP32 execution** checks that the native pretrained
model path and the online versus clean-informed top-k comparison work
on actual frozen checkpoints. It is **separate from the preregistered
16-board CUDA BF16 B4 scientific gate** and cannot substitute for it.

- Code: audit_b4_v2_online_svd.py at this PR head.
- Frozen checkpoints: gaoxin492, yagizdevre. Both are SHA-256 verified by the loader.
- Input subset: first four WB-Stall evaluation boards from the registered
  benchmark bundle, with per-board hashes recorded in the JSON.
- Each 21-invocation rollout exposes pass 20, the earliest validated readout.
- SVD factor count C=512 per module, top-k=307 (60% rounded), all four
  shared linear sites, frozen factors, no parameter updates.
- Arms: same-dtype target repeat, static rank 307, clean-oracle dynamic
  top-307, online current-activation dynamic top-307.
- Baseline uses zero ablation with residual off and no sphere rescaling.
- Paired board-level raw KL and four-module Hamming mask disagreement are
  serialized without scalar numerical floor subtraction.

## Compute

This PR creates a GitHub-hosted CPU workflow that runs each pretrained
checkpoint in its own job, saves JSON artifacts even on workflow failure
when output is present, and tests target identity closure (<1e-5 mean KL).
The workflow has a 35-minute timeout and uses no user GPU.

The pilot cannot settle final-pass KL at invocation 62, where the CUDA
BF16 identity control failed, and a positive pilot signal on four boards
does not establish statistical robustness. Successful source execution
supports proceeding to the full 16-board, 63-invocation CUDA experiment
already registered in B4_V2_ONLINE_SVD_PROTOCOL_20261117.md.

The trained CI weights remain unavailable in the extracted B4 artifact.
This protocol evaluates only the SVD comparator.
